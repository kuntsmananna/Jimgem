# simplify-repo — Jimgem (gems cocktail os)

Project-specific settings for the `simplify-repo` skill. CLAUDE.md and
AGENTS.md are the standard; this file only adds what the sweep needs on top.
CLAUDE.md is long because it records *why* things are the way they are —
**grep it for a file's or function's name before changing anything that looks
odd there.** Most "odd" code in this repo is a documented decision.

## Exclusions

`inventory.sh` already skips non-code files (`.sql`, `.md`, `.json`, images)
and `public/`. In addition, never review or edit:

- exclude: `scripts/migrate-*`
- exclude: `src/components/dashboard/DashboardOrdersPane.tsx`
- exclude: `src/components/orders/OrderDetailsPane.tsx`
- exclude: `src/lib/sumitProbe.ts`
- exclude: `scripts/sumit-probe.mts`
- exclude: `next-env.d.ts`

Why: migrations are hand-run against production and must stay idempotent and
unchanged once applied. `DashboardOrdersPane` and `OrderDetailsPane` are
**parked on purpose** (nothing imports them; the owner may want them back) —
a dead-code pass would delete them. The SUMIT probe is throwaway scaffolding
that goes away when the integration lands. Also leave `src/lib/schema.sql`
alone (excluded by extension): it runs top to bottom and must stay
semicolon-free in comments.

## Standards greps (run once in Phase 1)

Each hit is a candidate; check CLAUDE.md for an exception first. The comment
above each grep names the rule it checks.

```bash
# Design tokens, no hex in components (chartPalette.ts / globals.css are the homes)
grep -rnE '#[0-9a-fA-F]{6}\b' src/components src/app --include=*.tsx
# Money through currency()/count() in money.ts, never `₪${...}` (negative sign bug)
grep -rnE '₪\$\{|`₪' src --include=*.tsx --include=*.ts
# Failures through notify(), not alert()
grep -rn 'alert(' src --include=*.tsx --include=*.ts
# No faded ink below contrast (plain text-ink-soft, quiet via size/weight)
grep -rnoE 'text-ink(-soft)?/[0-9]+' src
# Hidden-until-hover must stay focusable: opacity-0 group-hover:opacity-100, not invisible
grep -rn 'invisible group-hover' src
# Secrets read only in their own module (db.ts, googleSheets.ts, sumit.ts, session.ts)
grep -rln 'process\.env' src
# Client Components must not value-import server-only lib modules
grep -rl '"use client"' src | xargs grep -nE 'from "@/lib/(orders|db|googleSheets|sheetImport|sumit|sumitSync|financials|expenses|settings|auth|session|version|backup)"' | grep -v 'import type'
# Writes go through sendWrite/writeOrNotify, not bare fetch with a method
grep -rnE 'fetch\([^)]*\{[^}]*method:' src/components
# Mobile is additive: no desktop class edited for phones — look for md: used to undo a phone style
grep -rnoE '\bmd:(block|flex|grid|inline)\b' src/components | head -50
# @/ alias, not deep relative imports
grep -rnE "from '(\.\./){2,}|from \"(\.\./){2,}" src
```

## Rules a "simplification" must not break

- **Read the bundled Next.js docs** (`node_modules/next/dist/docs/`) before
  touching any Next API — this Next 16 differs from training data (AGENTS.md).
- **Server/client split.** `src/lib/**` is server-only except `orderTypes.ts`,
  `icons.ts`, `flavorStyle.ts`, `roles.ts`, `foodCost.ts` and other files
  CLAUDE.md marks client-safe. Don't move values into a server module that a
  Client Component imports, and keep `version.ts` server-only.
- **Every Sheet reader stays in `sheetImport.ts`**, every SUMIT call in
  `sumit.ts`/`sumitSync.ts`. Don't "simplify" by moving a reader elsewhere.
- **SQL atomicity is single-statement CTEs** (no transactions on the Neon HTTP
  driver) — including the always-true `WHERE` / `EXISTS (SELECT 1 FROM
  updated_order)` guards that look redundant and are not. `ORDER_FIELDS` in
  `orders.ts` is the one column list; keep it that way.
- **Money math in `orderTypes.ts` is tested** — any change there must keep
  `npm test` green without editing the expectations.
- **Desktop doesn't move for a mobile change, and vice versa.** Keep
  `max-md:` variants and the `useIsMobile()` / both-copies-hidden patterns as
  they are; they were chosen deliberately to avoid hydration flashes.
- **Unlayered CSS in `globals.css` is unlayered on purpose** (beats Tailwind
  utilities). Don't move those blocks into `@layer`.
- Overlay, popover and undo machinery (`useOverlayDismiss`,
  `usePopoverDismiss`, `useDialogFocus`, `useUndoable`) encode subtle event
  ordering — refactor only with a test or a browser check.
- Redaction (`redact.ts`, `withStoredMoney`) and the role guards (`guard.ts`,
  `proxy.ts`) are security boundaries: simplify only if obviously equivalent,
  and keep their tests passing.
- `CLAUDE.md`'s top `@AGENTS.md` block is generated by `next dev`; don't edit it.

## Verify

- **Per batch (fast):** `npx eslint <touched files>` and `npx tsc --noEmit`;
  `npm test` whenever the batch touched `src/lib/**`, `src/components/orders/**`
  or anything with a `__tests__` beside it.
- **Full (Phase 3):** `npm run lint && npm test && npm run build && npx tsc --noEmit`
  — the same four steps `.github/workflows/checks.yml` runs on every push.
- **Visual:** for batches that touched components or `globals.css`, check the
  affected pages at 390px and 1280px wide (`npm run dev` needs `DATABASE_URL`;
  if the app can't run, say so in the report rather than claiming it was
  checked).

## Shipping

- **Bump `package.json` once, in the final commit** — a patch bump
  (`npm version <x.y.z> --no-git-tag-version`); a sweep is a tweak, not a
  capability. Stay below 1.0.0.
- **Push the working branch only** (Vercel builds a preview for it). Never
  touch `main` until the owner says to ship; then it is a fast-forward, no PR.
- Update CLAUDE.md in the final commit if the sweep renamed or moved anything
  it names.
